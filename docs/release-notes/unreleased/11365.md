# Bug Fixes

* The ordering of the transactions returned by `GetTransactions` and
  `lncli listchaintxns` is now
  [guaranteed to be stable](https://github.com/lightningnetwork/lnd/pull/11365):
  transactions with the same number of confirmations (e.g. transactions in the
  same block, or several unconfirmed transactions) keep their relative order,
  so the order within a page is deterministic. The default ordering itself is
  unchanged.

# New Features

## RPC Additions

* The `GetTransactions` RPC now accepts a
  [`reverse` flag](https://github.com/lightningnetwork/lnd/pull/11365) to
  return wallet transactions oldest-first, with unconfirmed transactions last.
  Previously, transactions were always returned newest-first
  ([#7316](https://github.com/lightningnetwork/lnd/issues/7316)). The flag only
  changes the order of the transactions within the response; pagination
  selects the same page either way.

## lncli Additions

* `lncli listchaintxns` gained a
  [`--reverse` flag](https://github.com/lightningnetwork/lnd/pull/11365) that
  exposes the new `GetTransactions` ordering option.
