# New Features

## RPC Additions

* WalletKit [adds explicit no-expiry
  leases](https://github.com/lightningnetwork/lnd/pull/11396). Set
  `LeaseOutput.no_expiry` or `FundPsbt.input_lease_no_expiry` to reserve unused
  outputs without a timeout. The owner can release the reservation, and the
  wallet removes the lease at the first confirmed spend.
  New no-expiry leases therefore do not expose confirmation progress through
  `confirmed_spend_height`.

# Improvements

## Breaking Changes

* WalletKit [replaces the confirmation-count RPC
  parameters](https://github.com/lightningnetwork/lnd/pull/11396)
  `LeaseOutput.release_after_spend_confs` and
  `FundPsbt.input_release_after_spend_confs` with the explicit no-expiry flags
  and removes the `release_after_spend_confs` response fields from
  `LeaseOutputResponse` and `UtxoLease`.
  The retired fields were introduced in v0.21.4-beta by
  [#11125](https://github.com/lightningnetwork/lnd/pull/11125).
  Callers must migrate and verify the returned `no_expiry` acknowledgement;
  requests using the retired count parameters now fail explicitly, including
  requests from old protobuf clients, instead of falling back to timed leases.
  After a confirmed spend, a reorg does not restore the removed lease. If the
  spending transaction is later removed, an otherwise unspent input can become
  selectable again.
