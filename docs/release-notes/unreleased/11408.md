# Bug Fixes

* [Fixed a startup stall on Postgres and SQLite
  nodes](https://github.com/lightningnetwork/lnd/pull/11408): pruning the
  switch's network result store at startup issued one database round-trip per
  stored entry. The store accumulates one entry per locally-initiated
  (outbound) payment, so on a node that sends a lot of payments the prune
  could take hours — and if the process restarted before it committed, the
  deletes rolled back and it never made progress. The store is now pruned with
  a single streamed read and one cascading delete instead of a round-trip per
  entry, so it commits in well under a second.
