# Improvements

## Breaking Changes

* lnd [no longer opens or accepts](https://github.com/lightningnetwork/lnd/pull/11422)
  new channels that use the static remote key commitment type. Explicit RPC
  requests and peer proposals are rejected, and automatic negotiation now
  requires both peers to support anchor channels.

  Existing static remote key and legacy channels are unaffected. They remain
  operable and report their original commitment type through the RPC. The
  `STATIC_REMOTE_KEY` enum value remains for this reporting, while the
  `tweakless` value of `lncli openchannel --channel_type` has been removed.

  To open new channels from Loop static addresses with lnd v0.22, upgrade to
  [Loop v0.36.0-beta](https://github.com/lightninglabs/loop/releases/tag/v0.36.0-beta)
  or later. This version defaults to anchor channels. If you pass
  `--channel_type=tweakless` to `loop static openchannel`, remove it to use
  the new default.

  Applications using LDK with anchor negotiation disabled cannot open new
  channels with lnd v0.22. LDK 0.2.8 disables anchor negotiation by default.
  Check whether your application enables `negotiate_anchors_zero_fee_htlc_tx`
  and handles on-chain fee bumping for anchor channels.

## Deprecations

* The `protocol.no-anchors` configuration option is deprecated and no longer
  has any effect. New channels require anchor support. A node that previously
  set `protocol.no-anchors=true` now advertises anchor support, along with the
  features that depend on it such as script enforced leases, and only logs a
  warning at startup. The on-chain reserve for anchor channels is then
  enforced when opening public channels. Peers that don't support anchor channels can no longer
  open new channels with this node, and this node can no longer open new
  channels with them.
