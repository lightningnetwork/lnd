# Technical and Architectural Updates

## BOLT 12 (Offers)

* [BOLT 12 invoice envelope in payment
  paths](https://github.com/lightningnetwork/lnd/pull/11532): the final hop of
  each blinded payment path of a BOLT 12 invoice now carries an invoice
  envelope with the invoice data, and a path id that authenticates it. The node
  derives the preimage from the path id, so it stores nothing when it answers
  an invoice request. A development table `bolt12_invoices` holds the
  envelope of a BOLT 12 invoice. Settlement of these invoices comes in a later
  change.

  The key of the payment path ids comes from an ECDH with the node key, which
  `signrpc.DeriveSharedKey` also gives. A caller with the `signer:generate`
  permission can therefore derive every BOLT 12 preimage that the node issues.
  Before, that permission could sign with the node key but could not learn
  preimages.
