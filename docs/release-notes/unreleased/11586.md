# Improvements

## Breaking Changes

* `lnd` now [enforces the simple taproot close feature
  dependencies](https://github.com/lightningnetwork/lnd/pull/11586) at
  startup and when connecting to peers. Configurations that previously
  started now fail with a `missing feature dependency` error if
  `protocol.simple-taproot-chans` or `protocol.rbf-coop-close` is combined
  with `protocol.no-any-segwit`. Peers whose `init` message advertises final
  simple taproot channels (bits 80/81) without simple close (bits 60/61), or
  simple close without `option_shutdown_anysegwit` (bits 26/27), are now
  disconnected as required by BOLT 1. This affects nodes running earlier `lnd`
  versions with both `protocol.simple-taproot-chans` and
  `protocol.simple-taproot-overlay-chans` enabled (e.g. Lightning Terminal
  with taproot assets channels), which did not enable RBF cooperative close
  before [#11279](https://github.com/lightningnetwork/lnd/pull/11279); they
  must upgrade to stay connected.

# Technical and Architectural Updates

## BOLT Spec Updates

* Final simple taproot channel support now [requires the complete feature
  dependency chain](https://github.com/lightningnetwork/lnd/pull/11586):
  `option_simple_taproot` requires `option_simple_close`, which in turn
  requires `option_shutdown_anysegwit`. The dependency chain is enforced for
  local, remote, and custom feature vectors while preserving `lnd`'s existing
  automatic simple-close enablement for final taproot channels.
