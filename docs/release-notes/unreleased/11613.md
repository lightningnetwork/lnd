# Bug Fixes

* Neutrino now stops supplemental confirmation scans at the surviving tip
  after a reorg. When a subscriber needs an earlier scan, LND clears a
  returned legacy confirmation or spend hint that would skip the prefix.
  This purge is skipped when cache queries are disabled. Re-enabling queries
  can therefore reuse a legacy height. If clearing a hint fails, the live
  scan continues, but a restart can reuse that height.
  A script confirmation can still be delivered while an earlier scan is
  pending. If the newer payment disconnects, a restart can find the older
  payment even when its scan result arrived before the disconnect.
  [PR #11613](https://github.com/lightningnetwork/lnd/pull/11613)
