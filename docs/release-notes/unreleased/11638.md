# Bug Fixes

* The `clock` module's `Clock` interface now has a
  [`TickAt`](https://github.com/lightningnetwork/lnd/pull/11638) method that
  registers a trigger for an absolute time in a single atomic step. Waiting for
  a deadline with `TickAfter(deadline.Sub(Now()))` sampled the clock and
  registered the trigger in two separate steps, so a clock that was adjusted in
  between scheduled the trigger after the deadline and the wakeup could be
  missed entirely. The invoice registry's HTLC auto-release timer, the invoice
  expiry watcher and the htlcswitch mailbox expiry now use `TickAt`. Behaviour
  with the default clock is unchanged.

# Improvements

## Breaking Changes

* Custom implementations of `clock.Clock` must now implement `TickAt(time.Time)`
  with the return type `<-chan time.Time`. A required method ensures that
  deadline callers can rely on atomic scheduling. An optional method with a
  `TickAfter(deadline.Sub(Now()))` fallback would retain the race for custom
  clocks. The root `go.mod` can drop its local `clock` replacement after a new
  `clock` module tag containing `TickAt` is published and the dependency is
  updated to that tag.
